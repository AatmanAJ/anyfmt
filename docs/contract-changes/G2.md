# Contract change requests from lane G2 (media tools)

## 1. `pdf.organize` must consume all inputs together

**What.** In `Sources/Shared/Specs.swift`, `ToolCatalog.all`, give the organise tool
`.combine(minimum: 1)` arity:

```swift
ToolSpec(ToolIDs.organizePDF, L("Merge / split / reorder"), glyph: "rectangle.grid.2x2", kinds: [.pdf],
         arity: .combine(minimum: 1), needsEditor: true, schema: ToolSchemas.organizePDF, suffix: "organized"),
```

**Why.** The tool is "merge / split / reorganise" and its `order` option addresses pages
across several PDFs (`input:page[:rotation]`). With today's default `.perFile` arity the job
layer would run it once per file, so a merge can never happen and an editor order that
references input 2 would be invalid for each single-file run. `OrganizePDFRunner` already
accepts any number of inputs; the editor already returns all inputs in one `EditorResult`.

**Workaround in the lane.** None needed in code; the runner and editor are ready. Until the
arity changes, a multi-PDF drag gets one organise job per file (no merge).

## 2. Optional human note on `ConversionOutput`

**What.** In `Sources/Engine/Engine.swift`:

```swift
public struct ConversionOutput: Sendable {
    public let files: [URL]
    /// One short line for the progress window's success state, e.g.
    /// "Cut on keyframes: 0:02.00 – 0:09.00". Nil for most jobs.
    public let note: String?
    public init(_ files: [URL], note: String? = nil) { self.files = files; self.note = note }
    public init(_ file: URL, note: String? = nil) { self.files = [file]; self.note = note }
}
```

**Why.** Lossless trims and splits snap cut points to keyframes. The editor already shows
the actual times live (status note plus a dashed outline on the filmstrip), but instant/CLI
runs have no way to tell the user. Source-compatible (defaulted parameter).

**Workaround in the lane.** Snapped times are logged (`Log.engine`), and the editors show them
before saving.

## 3. Not a contract, but blocks every engine in the app: helper signing

`scripts/embed-engines.sh` signs `Contents/Helpers/*` ad hoc **with hardened runtime**. The
helpers then can't load the ad-hoc-signed `Contents/Frameworks/libav*.dylib`:

```
dyld: Library not loaded: @rpath/libavfilter.12.dylib … not valid for use in process:
mapping process and mapped file (non-platform) have different Team IDs
```

Reproduce: `build/DerivedData/Build/Products/Debug/Halo.app/Contents/Helpers/ffmpeg -version`.

**Fix (verified in a scratch copy):** sign the helpers with an entitlements file that sets
`com.apple.security.cs.disable-library-validation = true` when the identity is ad hoc:

```bash
codesign --force --sign - --options runtime --entitlements Config/Helpers.entitlements "$f"
```

With a real Developer ID every binary shares the team ID, so the entitlement is only needed
for ad-hoc builds. App-hosted tests in this lane point `HALO_ENGINES_DIR` at `Engines/dist`
to avoid it.
